# DWD层（明细数据层）— 总表

> 根据事件更新，可视为实时更新，维护拉链表记录状态变化历史

---

## DWD-1：`dwd_client_snapshot`（客户拉链表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| client_id | bigint | 客户id |
| client_name | varchar | 客户名称 |
| company_id | bigint | 公司id |
| company_name | varchar | 公司名称 |
| status | int | 客户状态（0未下单，1活跃，2非活跃） |
| begin_date | bigint | 开始时间（毫秒时间戳） |
| end_date | bigint | 结束时间（毫秒时间戳，9999-12-31表示当前有效） |

**更新逻辑：** 监测 ods_client 的 status 变化，当客户状态发生改变时：
1. 关闭旧行：将当前有效行的 end_date 设为变化时间
2. 插入新行：begin_date = 变化时间，end_date = 9999-12-31 的时间戳

**查询方式：** 查某个时间点的客户状态：`WHERE begin_date <= 时间戳 AND end_date > 时间戳`

## DWD-2：`dwd_order_bus_snapshot`（订单业务拉链表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| order_id | bigint | 订单id |
| code | varchar | 订单号 |
| client_id | bigint | 客户id |
| client_name | varchar | 客户名称 |
| business_user_id | bigint | 业务员id |
| business_user_name | varchar | 业务员名称 |
| company_id | bigint | 公司id |
| approval_status | int | 审批状态（0已审批，1失效，2作废） |
| total_price | decimal | 合计金额 |
| bus_type | varchar | 数据生成节点/业务类型（本行由哪个业务事件产生） |
| begin_date | bigint | 开始时间（本次事件发生时间） |
| create_date | bigint | 创建时间（下单时间） |

（发货状态由另一张表专门维护，本表不含。）

**本质：** 记录订单全生命周期的事实表。订单每发生一个业务事件，就 append 一行，记录该时刻订单的快照 + 事件节点（bus_type）+ 事件时间（begin_date）。历史行不覆盖，取订单最新状态 = 该 order_id 下 begin_date 最大的行。订单在ODS新建但未审批时只在ODS、不进本表；进本表的订单即为已审批过的订单。

**触发事件（开发现状，均由 ods_order 事件驱动）：**
1. 订单审批完成（订单生效，首次进表）
2. 订单强制完成
3. 追加费用
4. 删除追加费用

每个事件 append 一行，bus_type 标记是哪个节点触发。

**待确认：** 目前无"作废/失效"触发事件，订单审批后被作废/失效时本表不会新增行，最新行仍停在"已审批"。若返单等场景需要排除审批后作废的订单，需请开发补"作废/失效"事件。

**用途（场景4返单）：** 进本表的订单即有效订单，取每个订单最新行、按 order_id 回到订单级；同一客户按下单时间排序，第1笔=首单，之后=返单。

## DWD-4：订单出货明细业务快照表【新建】

**来源场景：** 场景12 — 客户出货统计（出货侧）

| 字段 | 类型 | 说明 |
|------|------|------|
| 主键id | bigint | 自增主键 |
| 公司id | bigint | 所属公司 |
| 客户id | bigint | 取自发货单 |
| 客户名称 | varchar(100) | 取自发货单 |
| 订单id | bigint | 订单明细回连主单 |
| 订单号 | varchar(60) | 主单单号 |
| 订单产品id | bigint | 订单产品明细id（=发货明细里的订单明细id） |
| 产品类型 | int | 0配方产品,1中间品,2成品,3非化妆品,4原料,5包材,6辅料（取自发货单） |
| 产品id | bigint | 取自订单产品明细 |
| 产品编号 | varchar(500) | 取自订单产品明细 |
| 产品名 | varchar(500) | 取自订单产品明细 |
| 发货单id | bigint | 本行由哪张发货单触发【新增】 |
| 发货单号 | varchar(60) | 【新增】 |
| 下单数量 | decimal(40,20) | 取自订单产品明细 |
| 本次出货数量 | decimal(40,20) | 该发货明细单次出货数量【新增】；回退行记负数 |
| 已发货数量 | decimal(40,20) | 累计值 = 此前累计 + 本次 |
| 单价报价 | decimal(40,20) | 取自订单产品明细 |
| 本次出货金额 | decimal(40,20) | = 本次出货数量 × 单价报价【新增，可选，也可查询时现算】 |
| 进度状态 | int | 0未完成,1发货完成,2强制完成（已发货数量≥下单数量→1） |
| 数据生成节点 | varchar(100) | 发货出库 / 发货作废失效回退 / 强制完成 |
| 出货日期 | bigint | 发货单的发货时间（归月用） |
| 出货完成日期 | bigint | 发满那次出库的时间 |
| 开始时间 | bigint | 本次事件发生时间 |
| 删除状态 | int | 0未删除,1已删除 |
| 删除时间 | bigint | — |

**本质：** 只记"发货"事件的明细级快照表：发货单每发生一次有效出库，对其下每条发货明细 append 一行当时的快照；**没发过货的订单明细不进本表**。历史快照行不覆盖，取某明细最新出货状态 = 该订单产品id下 开始时间 最大的行。

**一、来源的 ODS 表**

| ODS 表 | 提供什么 |
|---|---|
| 发货单信息表（主表） | 事件源；客户id/客户名称、产品类型、发货时间（出货日期）、发货状态、审核状态 |
| 发货明细表 | 订单明细id、出货数量（本次）、发货单id |
| 7张订单产品明细表 | 产品id/编号/名、下单数量、单价报价、订单id |
| 订单表 | 订单号；发货单缺客户信息时兜底补客户 |

**二、ODS 字段变化 → DWD 增删改**

| ODS 变化 | DWD 动作 |
|---|---|
| 发货单.发货状态 → 3已出库（且审核状态=2已审核） | **增**：对该发货单每条发货明细各 append 一行快照——本次出货数量=发货明细.出货数量；已发货数量=该订单产品id此前累计+本次；已发货数量≥下单数量→进度状态=1发货完成、出货完成日期=本次出库时间，否则=0未完成；出货日期=发货单.发货时间；数据生成节点="发货出库" |
| 发货单.发货状态 → 4失效 / 5作废（该单此前已出库计过） | **增（回退行）**：每条明细 append 一行——本次出货数量记负数、已发货数量扣减该单数量、进度状态按扣减后重算；节点="发货作废/失效回退" |
| 订单产品明细.进度状态 → 2强制完成（订单侧事件） | **增**：append 一行，进度状态=2，节点="强制完成" |
| 订单产品明细.删除状态 → 1已删除（或主单删除） | **改**：该订单产品id在本表的行 删除状态置1、记删除时间（软删，不物理删） |
| 发货单.发货状态 0/1/2（未签名/未审/已审未出库） | **不动**：不产生行 |

**原则：** 本表只增不改（除软删），历史快照行不覆盖。

**口径：**
- 只统计 审核状态=2已审核 且 发货状态=3已出库 的发货单——一定要审核通过后才能出库发货；未审核/失效/作废的发货单是无意义数据，在DWD入口挡掉
- 客户信息直接取发货单冗余字段；发货单缺失时用订单id回连订单表补
- 出货数量/金额按月归集：∑本次出货数量、∑本次出货金额（按出货日期归月），用单次值不会重复算；已发货数量（累计）留给进度/发满判断用
- 发货类型：0正常发货计入；1预备发货/2预备发货已完成 是否计入出货统计【待与业务确认】

**说明：** 开发库目前没有这张，需新建。
