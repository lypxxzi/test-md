# 出货情况 — DWD 层表

> 统一说明：
> - 业务快照表由业务事件触发新增记录，历史快照不覆盖。
> - 查询某一统计时间点的数据时，按照业务主键取该时间点之前【开始时间】最大的一条记录。
> - 【产品类型】取值：0=配方产品，1=中间品，2=成品，3=非化妆品，4=原料，5=包材，6=辅料。

---

## 表1：【订单出货明细业务快照表】

### 一、数据来源

【发货单信息表】 【发货明细表】 【7张订单产品明细表】

### 二、粒度

一条发货明细发生一次出货业务事件生成一行。

【业务主键】【公司id】+【订单明细id】+【发货单id】+【开始时间】

【统计对象】订单明细的每次发货事件

### 三、字段

| 字段 | 说明 |
|---|---|
| 【公司id】 | 所属公司 |
| 【客户名】 | 客户名称 |
| 【客户id】 | 客户标识 |
| 【订单id】 | 主订单标识 |
| 【订单号】 | 主订单编号 |
| 【订单明细id】 | 订单产品明细标识 |
| 【物料id】 | 产品或物料标识 |
| 【发货单id】 | 本次发货所属发货单 |
| 【业务员id】 | 业务员标识 |
| 【业务员名】 | 业务员名称 |
| 【产品编号】 | 产品或物料编号 |
| 【数据生成节点】 | 发货出库、强制完成等事件名称 |
| 【开始时间】 | 本次业务事件发生时间 |
| 【出货完成日期】 | 订单明细发货完成或强制完成时间 |
| 【本次出货金额】 | 【本次出货数量】×【单价报价】 |
| 【已发货数量】 | 该订单明细截至本次事件的累计已发货数量 |
| 【出货日期】 | 发货单的发货时间 |
| 【进度状态】 | 0=未完成，1=发货完成，2=强制完成 |
| 【单价报价】 | 订单明细单价 |
| 【本次出货数量】 | 当前发货明细的出货数量 |
| 【下单数量】 | 订单明细下单数量 |
| 【产品名】 | 产品或物料名称 |
| 【产品类型】 | 0配方产品、1中间品、2成品、3非化妆品、4原料、5包材、6辅料 |

### 四、事件逻辑

#### 1、【发货单信息表】的【发货状态】变为“已出库”

对该发货单下每条发货明细新增一条快照：

- 【本次出货数量】=【发货明细表】的本次出货数量。
- 【已发货数量】=该【订单明细id】上一条快照的【已发货数量】+【本次出货数量】。
- 【本次出货金额】=【本次出货数量】×【单价报价】。
- 当【已发货数量】大于等于【下单数量】时，【进度状态】=1，【出货完成日期】=本次出库时间；否则【进度状态】=0。
- 【出货日期】=发货单日期，【数据生成节点】=“发货出库”。

#### 2、订单明细强制完成

对对应【订单明细id】新增一条快照：

- 【进度状态】=2。
- 【出货完成日期】=强制完成操作时间。
- 【已发货数量】保留实际累计发货数量。
- 【数据生成节点】=“强制完成”。

### 五、能力注释

【支持】每次发货数量、累计已发货数量、实际出货金额、订单明细完成状态和完成日期查询。

【不支持】从未发生发货且未强制完成的订单明细；完整订单明细范围需关联【订单明细业务快照表】。

## 表2：【订单明细业务快照表】

### 一、数据来源

【7张订单产品明细表】

### 二、粒度

一条订单明细发生一次业务事件生成一行。

【业务主键】【公司id】+【订单明细id】+【开始时间】

【统计对象】订单产品明细

### 三、字段

| 字段 | 说明 |
|---|---|
| 【公司id】 | 所属公司 |
| 【客户名】 | 客户名称 |
| 【客户id】 | 客户标识 |
| 【订单id】 | 主订单标识 |
| 【订单号】 | 主订单编号 |
| 【订单明细id】 | 订单产品明细标识 |
| 【物料id】 | 产品或物料标识 |
| 【业务员id】 | 业务员标识 |
| 【业务员名】 | 业务员名称 |
| 【产品编号】 | 产品或物料编号 |
| 【出货日期】 | 订单明细约定交货日期 |
| 【数据生成节点】 | 订单审批完成、订单强制完成等事件名称 |
| 【开始时间】 | 本次业务事件发生时间 |
| 【预算单价成本】 | 订单明细预算单件成本 |
| 【单价报价】 | 订单明细单价 |
| 【下单数量】 | 订单明细下单数量 |
| 【产品名】 | 产品或物料名称 |
| 【产品类型】 | 0配方产品、1中间品、2成品、3非化妆品、4原料、5包材、6辅料 |

### 四、事件逻辑

#### 1、订单审批完成

对主订单下每条有效订单明细新增一条快照，【数据生成节点】=“订单审批完成”。

#### 2、订单强制完成

对受影响的有效订单明细新增一条快照，【数据生成节点】=“订单强制完成”。

查询某一时间点的订单明细范围时，每个【订单明细id】取【开始时间】最大的一条记录，并排除已删除明细。

### 五、能力注释

【支持】取得主订单下完整的有效订单明细范围，以及产品类型、下单数量、报价、成本和约定交货日期。

【不支持】实际发货数量、发货金额和发货完成状态；需关联【订单出货明细业务快照表】。

## 表3：【订单业务快照表】

### 一、数据来源

【订单表】

### 二、粒度

一张主订单发生一次业务事件生成一行。

【业务主键】【公司id】+【订单id】+【开始时间】

【统计对象】主订单

### 三、字段

| 字段 | 说明 |
|---|---|
| 【公司id】 | 所属公司 |
| 【客户名】 | 客户名称 |
| 【客户id】 | 客户标识 |
| 【订单id】 | 主订单标识 |
| 【订单号】 | 主订单编号 |
| 【合计金额】 | 主订单合计金额 |
| 【开始时间】 | 本次业务事件发生时间 |
| 【数据生成节点】 | 订单审批完成、订单强制完成、追加费用等事件名称 |

### 四、事件逻辑

订单审批完成、订单强制完成、追加费用或删除追加费用时，新增一条主订单快照。

查询某一统计时间点的主订单时，每个【订单id】取该时间点之前【开始时间】最大的一条记录，并排除已删除订单。

### 五、能力注释

【支持】主订单、客户和主订单合计金额的历史快照查询。

【不支持】订单明细范围和实际出货状态；需关联【订单明细业务快照表】和【订单出货明细业务快照表】。

## 表4：【客户拉链表】

### 一、数据来源

【客户表】

### 二、粒度

一个客户的一段状态有效期生成一行。

【业务主键】【公司id】+【客户id】+【开始时间】

【统计对象】客户状态

### 三、字段

| 字段 | 说明 |
|---|---|
| 【公司id】 | 所属公司 |
| 【客户名】 | 客户名称 |
| 【客户id】 | 客户标识 |
| 【业务员id】 | 业务员标识 |
| 【业务员】 | 业务员名称 |
| 【客户状态】 | 未下单、活跃、非活跃等客户状态 |
| 【开始时间】 | 本条状态开始生效时间 |
| 【结束时间】 | 本条状态结束时间 |
| 【数据生成节点】 | 客户新增或客户状态变化事件 |

### 四、更新逻辑

客户新增时插入第一条记录；【客户状态】或归属业务员发生变化时：

1. 将当前有效记录的【结束时间】更新为变化时间。
2. 新增一条记录，【开始时间】=变化时间，【结束时间】=最大时间。

查询某一时间点的客户状态时，使用“【开始时间】小于等于查询时间，且【结束时间】大于查询时间”取得有效记录。

### 五、能力注释

【支持】任意时间点的客户状态、客户归属业务员和客户基础信息查询。

【不支持】订单、订单明细和出货指标。
